# BLOCKERS

Ce que la plateforme **ne peut pas** faire ici, avec le contournement retenu. Un blocage
non écrit devient une surprise ; celui-ci est écrit.

| Flux | Story | Cause | Contournement retenu | Date |
|:--|:--|:--|:--|:--|
| S13 | S13-04 | Le token Jira fourni est refusé par `meltingcode.atlassian.net` (`AUTHENTICATED_FAILED`), en Basic comme en Bearer, sur `/rest/api/3` comme sur `api.atlassian.com/ex/jira/{cloudId}`. Le site et le compte sont bons — le cloudId résout, l'e-mail est celui du compte — donc c'est le token qui est expiré ou révoqué. | L'adaptateur Jira reste vérifié **contre le protocole** (14 tests, transport simulé) : forme des requêtes, choix de la transition, ADF, webhooks. Ce qu'aucun test ici ne prouve : qu'une instance accepte ces appels. Un token valide lève ce point en dix minutes — la suite `tests/live` est écrite et attend ses variables. | 2026-09-19 |
| S7 | S7-05, S7-08 | La pile montée sur kind est volontairement petite : Temporal de développement (SQLite), Postgres simple, pas d'Argo Rollouts. Les valeurs HA et le canary de la plateforme ne peuvent pas être éprouvés à cette échelle. | Ce qui est prouvé sur cluster l'est vraiment : l'image du dépôt démarre, les migrations passent sur un vrai Postgres, les workers parlent à Temporal, un worker tué est remplacé. Ce qui reste — Temporal à trois nœuds, CNPG à trois instances, Rollouts — demande un environnement de la taille de staging. | 2026-09-19 |
| S12 | S12-05 | Un nœud spot ne se perd pas sur un kind local : le scénario « le nœud disparaît pendant un run » n'a pas d'équivalent fidèle ici. | La perte d'un **worker** est jouée sur cluster (pod supprimé, remplacé, API servie pendant ce temps) et la reprise sans double coût est prouvée par le test de replay. Ce qui manque est la panne d'infrastructure, pas la panne de processus. | 2026-09-19 |
| S13 | S13-05 | Aucun abonnement Azure joignable. | L'`Executor` ACA est écrit et testé contre le protocole ARM documenté (18 tests) et le template `github-aca` le met en œuvre. Un `azure-devops-aca` complet demanderait en plus un tracker Azure Boards et un CD sur révisions ACA. | 2026-09-19 |
| S11 | E-02, E-04, E-09 → E-14 | Ces stories vivent dans `VargaFoundation/ecphoria` et dépassent l'intégration dont Choregos a besoin. | E-01 (triage), E-03, E-05, E-06 et E-07 sont livrés et poussés sur `main` ; l'intégration est vérifiée de bout en bout depuis Choregos (10 tests live). Le reste — feature flags Cargo, schémas de faits, bench, chart durci, releases, sécurité, docs — est du travail Ecphoria, pas du travail Choregos. | 2026-09-19 |
