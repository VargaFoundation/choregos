| S69-01 | S69 | ✅ | — | The publishing identity is one file ([ADR 0156](../../adr/0156-the-publishing-identity-is-one-file.md)): `packages/core/src/choregos_core/publishing.json` holds who publishes Choregos and where (owner, image and chart registry, source repository, documentation, security contact, the agent's commit address, the plugins' repository and signed index); the values published today are unchanged. The code reads it through `choregos_core.publishing.PUBLISHING`: the orchestrator's default runner image, the `User-Agent` contact, the release pages of the CLI's self-update, of the API's downloads and of the install scripts it serves (substituted like the instance's address), the default documentation address of the API and of its MCP docs tools, the runner's default commit address, the plugin lock tool and the CLI reference generator. The console reads `apps/web/src/lib/publishing.json`, a byte-for-byte copy, through `@/lib/publishing` (About panel, release links, documentation base, administration links, the demo's plugin source). The cosign identities are derived (`<repository>/.github/workflows/<file>@<ref>`), not stored. The 84 files that cannot read JSON (chart values and helpers, Kyverno policies and their tests, Argo CD Applications, workflows, `CODEOWNERS`, Dockerfiles, compose files, pipeline templates, `plugins.lock`, the contract's examples and `docs_url` description with the types generated from it, plugin fixtures, documentation pages) are listed in `tools/publishing_identity.py`; `make publishing-check` checks them and `make publishing-rewrite FROM=<ref>` rewrites them from the definition; history (ADRs, `docs/plan/`, applied migrations, trial results) is never rewritten. Measured: `git grep -l -i vargafoundation` 148 files before, 100 after (1 definition, 1 copy, 81 derived, 17 history); code files (`.py`, `.ts`, `.tsx`, `.sh`, `.ps1`) spelling the identity, 59 before, 0 after outside an applied migration and the generated `packages/contracts/ts/api.ts`. **Proves**: `tests/tools/test_publishing_identity.py` (no tracked file outside the definition, its copy, the derived list and history spells a value, in any case, plain or with its dots escaped, the owner only as a GitHub path segment so that a publisher's name in prose is not it; a literal in code, code listed as derived, a value in another case, a stale or absent entry and a drifted copy are each refused; on a copy of the tree with every value moved to another owner, registry, forge and domain, the rewrite changes every derived file and the copy, leaves nothing of the former identity outside history and does not touch history; moving the owner alone leaves an unchanged registry alone; the chart's registry and default plugin source, the outpost chart's registry, the image policy's references and subject and `plugins.lock`'s index and signatures are the definition's); `packages/core/tests/test_publishing.py` (what follows from the values, values that would not compose refused); the runtime uses compare with the definition (`apps/api/tests/test_cli_downloads.py`, `test_docs_url.py`, `test_offline_plugins.py`, `test_plugin_servers.py`, `tests/charts/`, `tests/ci/test_nightly_job.py`, `tests/dev/test_local_install.py`, `apps/web/tests/about-panel.test.tsx`, `docs-links.test.tsx`, `integrations-cli-download.test.tsx`); `make docs-cli` regenerates `docs/cli.md` byte for byte. **Does not prove**: the whole suite green on a rewritten tree (the rewrite is checked for what it leaves, not by running every test after it); anything outside the repository: images and charts pushed under another namespace, the GitHub teams `CODEOWNERS` names, plugins re-signed under another identity and `plugins.lock` refreshed, a documentation site redirect; admission policies accepting two identities during a transition (the rewrite replaces, it does not duplicate). The plugin source name `varga`, persisted in `org_plugins.source` and `org_plugin_approvals.source` since migration `b8d0f2a4c6e1` and named by the chart's `sources` and `defaultPlugins`, is not an identity value: renaming it is a data migration of its own, released with those two lists (ADR 0156 §8). |
