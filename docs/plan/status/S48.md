| S48-01 | S48 | ✅ | — | A workflow chooses its next step from the agent's answer (contract change, ADR 0106; product owner, 2026-10-28): a transition may carry `when`, conditions on the outputs of the work item's last stage — a value, a list, or `equals`/`in`/`not_in`/`gt`/`gte`/`lt`/`lte` — and `select_transition` takes the first transition whose `when` holds, one without `when` being the default. Before, it read only an incoming event's id and otherwise took the first transition declared, so an agent's `outcome: reply` or `done: false` could not choose a path. Numbers and booleans written as strings compare as such; a missing output never matches. The validator refuses an unknown output name (`when.unknown_output`) and a state with no default exit (`when.no_default`). The interpreter keeps the last stage's outputs (`last_outputs`, from the activity's result, so replays agree), carries them across `continue_as_new`, and a restarted interpreter reads them back in `load_context`; the local mode chooses the same way. **Proves**: `packages/core/tests/test_branch_on_outputs.py` (conditions, selection, validator), `apps/orchestrator/tests/test_branch_on_outputs.py` on Temporal's test server (an agent loops until it answers `done: true`; a low confidence lands in a person's state; a restarted interpreter reads the last answer back), both red without the engine change (checked); histories `wi-branch-on-outputs-loop-S48-01.json` and `wi-branch-on-outputs-unsure-S48-01.json` archived; every archived history replays. **Does not prove**: the console showing `when` on the map (it shows the transitions, not their conditions); nothing run on a tenant. |
| S48-02 | S48 | 🟡 | #1090 | Each organisation can sign in with its own identity provider (ADR 0108; product owner, 2026-10-28: "a customer must be able to come with its own SSO"). The core gains one seam, `tenant_sign_in.declare_sign_in_resolver`: an extension maps a sign-in link (`/auth/login?org=<slug>`) or the domain of the address typed on the console's sign-in page (`login_hint`, passed on to the provider) to a `TenantSignIn`, either an `OidcProvider` the core drives (issuer, client id and secret, scopes, explicit endpoints, `require_email_verified`, groups claim, `groups_map`) or the route of the extension that starts SAML. The core confines whatever a tenant's provider vouches for, OIDC or through `terminer_la_connexion(org=…)`: the address's domain must resolve to that same tenant, roles land on that tenant only, subjects are stored as `tenant:<org id>:<sub>`, a tenant's discovery failure is a 502 never a Keycloak guess, and the tenant chosen at login is carried in the signed `state` and resolved again at the callback. Without a resolver nothing changes. *Admin → Platform* gains the row `oidc.per_organisation`. **Proves**: `apps/api/tests/test_tenant_sign_in.py` (20: a `groups_map` translating provider group ids, routing by domain and by link, SAML start, fallback to the instance, the domain, role, subject and `email_verified` guards each red when removed (checked), no discovery guess, explicit endpoints, a tenant lost mid-sign-in), `test_platform_identity.py` +1, `apps/web/tests/dev-sign-in.test.tsx` +2. **Does not prove**: storing and editing a tenant's settings, SAML assertion verification and domain-ownership proof, which belong to the enterprise edition (ADR 0024) and are not in this repository; a live IdP; roles a tenant's provider stops granting are still not revoked (SEC-2, S47-05). |
