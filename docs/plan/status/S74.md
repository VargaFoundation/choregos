| S74-01 | S74 | 🟡 | — | **An organisation may own a host: the decision, the core seam, theme by host** ([ADR 0175](../../adr/0175-an-organisation-may-own-a-host.md), amends the "one sub-domain per tenant" of ADR 0108). Core: `tenant_host.declare_host_resolver` (one provider, host to organisation slug or `None`, CE default none); `GET /api/v1/theme` resolves the organisation from `X-Forwarded-Host` / `Host` and serves it before `?org=` (no new query parameter, the OpenAPI contract is unchanged), names it in `X-Choregos-Host-Org`, `Vary: Host, X-Forwarded-Host`; console: the root layout reads the look and the host's organisation (`servedLook`), forwards the visitor's host, memoises a tenant host under the host alone, does not swap the look after hydration, and `/login` on a tenant host sends `org=<host organisation>`. **Proves** (API, run here): `apps/api/tests/test_tenant_host.py` (host wins over `?org=`; `X-Forwarded-Host` first entry, lower-cased, port stripped, wins over `Host`; unknown host keeps `?org=`; an address, a name without a dot, an overlong or non-ASCII value never reach the resolver; an answer that is not a slug, a raising resolver, an async resolver; a resolver alone still names the organisation; `Vary`; one resolver, reset); mutants killed: host not preferred over `?org=`, `X-Forwarded-Host` ignored, host validation removed. **Proves, written but NOT run on this workstation (no node, no pnpm: vitest, eslint, tsc and the build run in CI only)**: `tests/tenant-host.test.ts`, `tests/served-theme-server.test.ts` (forwarded host, host before cookie, memo keyed by host, no leak across hosts, non-DNS names not forwarded, header accepted only as a slug), `tests/organisation-theme.test.tsx` (no swap on a tenant host), `tests/dev-sign-in.test.tsx` (the sign-in link implies the host organisation). **Does not prove / not done (out of scope, each its own story)**: signing in on a tenant host (OIDC `redirect_uri` per host, host-only session cookies, `origin_guard` / CORS runtime allowlist, `CHOREGOS_PUBLIC_HOSTS` growing with claims, Keycloak redirect URIs, SAML per host); the rule for a member of another organisation on a tenant host is decided in the ADR and not implemented; a per-organisation public URL for links, MCP, A2A and notifications; chart, ingress and TLS (HTTP-01 is infra#1595); no real browser, ingress or DNS exercised; the enterprise edition's claims table and TXT verification are in the paired choregos-ee PR, and nothing runs end to end until it is merged and the core release carrying this seam is pinned in `COEUR` |
| S74-02 | S74 | 🟡 | — | **Sign in and use the console on a verified tenant host** ([ADR 0175](../../adr/0175-an-organisation-may-own-a-host.md), amendment). Core: `/auth/login` on a verified host implies its organisation and sends `redirect_uri=https://<host>/api/v1/auth/callback`; the host is signed in the `state`, the callback must come back to it (still verified) and uses the same redirect URI for the code exchange; host-only handshake and session cookies; redirect targets bounded to the instance and the host (`/\x` now refused everywhere); a member of another organisation only is refused with 403 and nothing stored; `origin_guard` accepts a verified host's own origin and `internal_api_guard` treats it as public, at runtime, through `tenant_host.verified_host_cached` (30 s memo, bounded); SAML kept canonical. **Proves** (run here, 51 tests in `apps/api/tests/test_tenant_host_sign_in.py`): callback per host; unverified, claimed, non-DNS and spoofed hosts get the canonical callback and no `h`; `?org=` cannot override the host; no `Domain` on either cookie; token exchange uses the host's redirect URI; member of the host's organisation signs in and lands on the host; non-member 403, no cookie, no user stored; login/callback host mismatch (four cases) and a claim withdrawn in between refuse before the code is exchanged; ten off-host redirect targets refused, three legitimate followed; origin guard: verified own origin passes, claimed host, foreign, another verified host, sub-domain, wrong scheme, port and `null` refused, no resolver or a failing one refuses, cache hit then expiry within TTL, cache bound; run API not served on a verified host and still served elsewhere; SAML tenant sent to the canonical start route. Mutants killed (suite red without each): non-member check removed, callback host check removed, origin not tied to the request host, origin not checked against the verified table, run-API guard blind to verified hosts, backslash target allowed, host not implying its organisation. **Does not prove / not done**: no real Keycloak, browser, ingress or DNS (the instance's relay forwarding `X-Forwarded-Host` and the ingress overwriting a client-supplied one are assumed, not tested); the Keycloak `choregos` client must list each host's callback (infra, operator: `platform-realm.json`; nothing automated); no web change, so the not-a-member page and the switcher confined to the host's organisation are open, and a session is not confined to one organisation; a tenant's own OIDC provider must register the callback (the enterprise edition should show it); SAML per host; per-organisation public URL for links, MCP, A2A, notifications and device sign-in (S74-03); chart, ingress, TLS (S74-04); a verified host with a port is not supported |
| S74-04 | S74 | 🟡 | — | **The chart serves an organisation's own hosts** ([ADR 0175](../../adr/0175-an-organisation-may-own-a-host.md), amendment S74-04). `global.customHosts` (`templates/custom-hosts.yaml`): per host, routing to the console and the API as the canonical host (the API's paths, then `/` to the console) as one Ingress with `tls`, as an NGINX Inc. master (host + TLS secret, no path) with two minions, or as an HTTPRoute; plus a cert-manager `Certificate` (HTTP-01) from a configurable Issuer (`choregos-issuer` of infra#1595); the hosts also go to `CHOREGOS_PUBLIC_HOSTS`, so the run's API is closed on them before any proof. `docs/deployment.md` documents the end-to-end procedure (TXT claim, CNAME, chart value, Keycloak redirect URI). **Proves** (run here, `tests/charts/test_custom_hosts.py`, 22 tests over real `helm template`): nothing rendered and the public hosts unchanged by default; the plain Ingress's paths equal the API's own route's, then the console; the Certificate's host, issuer and secret match the Ingress's TLS secret; master has the host, the TLS and no path, minions carry the paths and `minion`, and the operator's annotations cannot change the master's type; HTTPRoute matches equal the canonical route's; hosts in `CHOREGOS_PUBLIC_HOSTS`; one set of objects per host; the render refuses a wildcard, a scheme, a port, upper case, a bare label, a host already routed (API, console, run door), two hosts with one object name, an enabled certificate without an Issuer and an unknown kind. Mutants killed: the host list removed from `CHOREGOS_PUBLIC_HOSTS`, the host-name check loosened. **Does not prove / not done**: no cluster, no cert-manager, no NGINX Inc. controller: whether a master whose TLS secret does not exist yet is served, whether the HTTP-01 solver Ingress is accepted beside the master (the Issuer likely needs `ingressTemplate` with `nginx.org/mergeable-ingress-type: minion`, which infra#1595 does not set), a real issuance, and that the ingress overwrites `X-Forwarded-Host`, are all unverified; the HTTPRoute's Gateway listener is the operator's; no `helm unittest` suite (the Python tests render the chart, as `tests/charts/` does); the Issuer, TXT proof, CNAME and Keycloak redirect URI are operator steps; the DiametralGroup/choregos-deploy values (empty list) are a follow-up after the chart is released. |
