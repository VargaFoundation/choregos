Source: Vincent's request of 2026-10-12 (items 0 to 13). Each item was checked against the code at
`f425efa` and against the competition (Microsoft Copilot Studio / Agent 365, Salesforce Agentforce,
AWS Bedrock AgentCore, Google Gemini Enterprise, OpenAI AgentKit, Dust, Langfuse/LangSmith).

This plan is written in English: item 13 asks for it, and it supersedes the "docs/plan stays French"
rule of ADR 0039 §3 once the ADR of stream S34 is accepted.

## 1. Challenges and amendments, item by item

### Item 0 — Agent builder

**Keep:** an agent is skills + tools + model + knowledge + optional memory, plus instructions,
limits and budget (already in the spec).

**Amend:**
- **Knowledge is an org object, not an agent field.** A `KnowledgeBase` is created once (sources,
  sync, index) and *attached* to agents by reference, pinned like a skill. Ten agents can share the
  architecture framework without ten copies.
- **Knowledge must respect who may read it.** A SharePoint library an agent can read is readable by
  every requester of that agent. Either the KB is restricted to a project/group (simple, chosen), or
  results are trimmed by the requester's rights (Graph ACL trimming — expensive, later).
- **Memory is a scope, not a store choice**: `none | project | agent`. Ecphoria stays the engine
  (ADR 0007); the agent declares where its learned facts go.
- **Add a lifecycle**, which the request omits and every competitor has (the Microsoft Learn page
  "Monitor, update, and retire your plugin or agent" is exactly this): owner, status
  `draft → active → deprecated → retired`, a retire checklist that revokes tokens, unpins projects
  and records the final state; "unused for 60 days" surfaced to the owner; ownership transfer that
  carries the agent's credentials.
- **Add "try it" before publish**: run the draft version on a sample input in fakes-free mode with
  a tiny budget, and the agent's eval suite (ADR 0020) as a publish gate when one exists.
- **Keep the definition as data (YAML/JSON) with a form on top**, not a visual canvas: OpenAI is
  shutting down its visual Agent Builder on 2026-11-30, 13 months after launch.

### Item 0b — Skills import

**Keep:** import from a GitHub repo and from a zip.

**Amend — the security gate is the feature, not the import:**
- Snyk scanned 3,984 public skills in 2026: 13.4 % had a critical issue; the first malware campaign
  used 30+ skills. Importing "GitHub's useful skills" without a gate turns Choregos into a
  distribution channel.
- **Git import pins a commit SHA**, never a branch; an update is a new version proposed to a human,
  never automatic (bait-and-switch is the documented attack).
- **Risk tier computed at import**: `low` (markdown only), `medium` (references, assets), `high`
  (scripts, network URLs, credentials patterns, MCP references). High needs an approval by someone
  other than the importer.
- **Static scan**: prompt-injection patterns, hidden Unicode, obfuscated scripts, outbound URLs.
- **Licence check**: read the repo's licence; refuse or flag non-open ones. Note: several skills in
  `anthropics/skills` (docx, pptx, xlsx, pdf) are source-available, not open source.
- **Allowlisted sources** per org (e.g. `anthropics/skills`, the org's own repos); anything else
  needs `org_admin`.
- **Revisit the 64 files / 512 KiB limit**: real skills with `references/` exceed it; raise to e.g.
  256 files / 5 MiB with the risk tier doing the work.
- Already right and kept: `allowed-tools` refused, runner network closed, digest re-checked.

### Items 1 and 6 — Budget at launch and guardrails (one stream, P0)

The request asks for a budget field. **The field is useless until enforcement is fixed**, because
today an agent *can* burn the budget:

| # | Hole (file:line) | Effect |
|:--|:--|:--|
| a | The runner never emits `reason="budget"`; a gateway refusal ends as `agent_silencieux` / `invalid_result` (`runner.py:420-434`) | `on_budget_exceeded` never fires; `retry_or_escalate` retries **with a fresh key** (`stage.py:334-336`) |
| b | The ticket check runs after the stage (`interpreter.py:425-431`); each key is minted at the full `stage_usd`, not at the remaining ticket budget | Overshoot up to one full stage per stage |
| c | `cost_usd` lives in workflow memory; a restarted interpreter starts at 0 and ignores `item.totals` (`interpreter.py:253`) | Budget resets on resume |
| d | "Replay the stage" and resume-after-escalation reset attempts (`interpreter.py:86-89,887`) | A human click re-opens the full retry budget |
| e | Tool-call costs (`kind=tool`) are not in the ticket counter | Under-count |
| f | `max_turns` not enforced; `attempts.default_max` dead; no org ceiling; `daily_project_usd` displayed, never enforced; the LiteLLM team cap is never created (`provisioning.py:255-263`) | No hard stop above the stage |

Worst case today ≈ stages × 10 attempts × `stage_usd`.

**Plan:**
- **Reservation model**: a run's key is minted at `min(stage_usd, agent.run_usd, ticket_remaining,
  project_day_remaining, org_month_remaining)`; when that minimum is below a floor, the stage does
  not start and the ticket goes `needs_human, reason=budget`.
- The counter is read from the ledger (`item.totals` + tool costs), not from workflow memory.
- The runner maps a gateway budget refusal to `reason=budget`; `on_budget_exceeded` routes to
  `needs_human`, **never to a retry**.
- Retries share the ticket budget; a human "replay" grants a stated top-up, recorded in the audit.
- **Budget at launch** = an optional `budget_usd` on `WorkItemCreate` and on the workflow DSL
  (`budget: {ticket_usd, on_exceeded}`), bounded by the project policy (422 if wider).
- **Org ceiling**: an org policy the project policy may only tighten (same rule as agent overrides).
- **Guardrails enforced, not prompted**: `max_turns` cut by the runner; loop detection (same tool +
  same arguments N times; same failure signature on two consecutive attempts → stop retrying);
  `max_stages_per_ticket`; an agent **kill switch** and a **monthly cap per agent with hard stop**
  (Copilot Studio turns the agent off at its monthly limit); alerts at 50/80/100 % (Slack exists).
- Remove `attempts.default_max/by_role` or wire it; dead config is a lie in the policy editor.

### Item 2 — Spend screen

- Add `agent_slug`, `agent_version`, `workflow` (name + version) and `work_item_id` to the ledger
  (migration + backfill from `runs`); `group_by` gains `agent|workflow|work_item|project`.
- One `/costs` page (org scope; project scope pre-filtered): spend over time, budget vs actual with
  forecast to month end, top agents / workflows / tickets, breakdown by model and by tool, CSV of
  any grouping. Langfuse and LangSmith only *alert*; enforcement stays at the gateway (§1).
- Currency: the ledger stores USD and EUR; the screen shows the org's currency, EUR by default (D4).

### Item 3 — Specialist agents

**Challenge:** more agents is not better. Routing degrades past 30–40 choices (Copilot Studio's own
guidance), and no vendor ships a curated architecture/security/legal catalogue — they are community
collections of uneven quality. Each new agent must ship with: a role in a shipped workflow, an output
contract (§4), the tools it needs, and an eval set. An agent with no tool to act on is a prompt.

| Agent | Keep / amend | Needs |
|:--|:--|:--|
| architect (exists) | Keep; becomes useful only with a KB (§5): challenges a request against the enterprise framework, writes an ADR (MADR 4) | KB attach, citations required |
| security-reviewer (exists) | Keep for design and code review (threat model, OWASP ASVS) | SAST/SCA output as input |
| secops | **Amend**: supply chain and runtime posture — dependency CVEs, SBOM, secrets, container scan, IaC misconfig. Runs scanners (already in the runner image) and *interprets* them; does not replace them | scanner tools, SBOM artefact |
| legal | **Amend to "compliance"**: licences of dependencies, GDPR/data-processing impact of a change, third-party terms. Output is a review with a mandatory human gate; never "legal advice" | licence DB, KB of the org's policies |
| devops | Keep: release readiness, rollout plan, reads logs and metrics after deploy. **Production stays behind the train** (ADR 0006): the agent proposes, the train executes | read-only Loki/Prometheus/Grafana MCP connectors |
| netops | **Separate agent (D3)**, for our own estate first: pfSense, Cilium, nginx. Reads state, proposes changes as code; every write is a governed action (ADR 0035) with a human approval, production through the train | connectors: pfSense (REST API package, read first), Cilium (`CiliumNetworkPolicy` in the GitOps repo, Hubble flows read-only), nginx (config in the repo, `nginx -t` in the runner) |
| docs / technical writer | Keep: user docs, changelog, API docs from the diff; checks docs updated (DoD) | repo docs paths |
| UX/UI | Keep, with the **design system as a skill + KB** (tokens, components, brand rules, screenshots) and an accessibility check (axe) | Playwright screenshots, axe |
| QA | Keep, and make it sharper than coverage: test plan from the spec, edge cases (boundaries, empty, concurrency, errors), **mutation testing** — the project's own rule "nothing is ✅ without a test that fails in its absence" is mutation testing | mutmut / Stryker in the runner image |

Ship them in a template `software-delivery-governed` (study → architecture → plan → implement →
QA + security + compliance in parallel → docs → train → devops verify), each with gates.

### Item 4 — Agent outputs (artifacts)

- **Artifact becomes first-class**: `{name, type (markdown|json|file|diagram|report), version,
  produced_by (agent, version, run), digest, storage_url}`, stored in the object store (RustFS in
  dev), attached to the work item. Markdown documents stay inline; files (pdf, docx, png, sarif) go
  to the store.
- Declared in the DSL as today (`Transition.outputs/inputs`), now typed; a missing declared output
  fails the stage (it does today only for the four software documents).
- **API**: `GET /work-items/{id}/artifacts[/{name}[@version]]`; the work item page gets an
  "Artifacts" tab with a viewer (markdown, SARIF table, image, download) and the hand-off receipts
  (S25-04) linking each artifact to its consumers.
- Consumption: downstream agents receive inputs as files in the workspace (`.choregos/inputs/`)
  rather than only inlined in the prompt — large reports otherwise eat the context.

### Item 5 — Knowledge bases

**Challenge the vocabulary:** nothing is "trained". A knowledge base is **ingested and indexed**;
fine-tuning is out of scope.

**Challenge the vector DB:** the 2026 evidence (Anthropic's guidance, agentic-search papers) says:
under ~200k tokens put the corpus in context; above, agentic search over files reaches >90 % of RAG
quality; hybrid retrieval (BM25 + embeddings) with contextual chunks is the robust default when
search must be fast or the corpus large. A dedicated vector database is not needed: **PostgreSQL 16
is already there (D10); add `pgvector` + full-text search** in the same database, with RLS.

**Plan:**
1. **Ingestion**: upload (docx, pptx, xlsx, pdf, md, html) and connectors (SharePoint/OneDrive via
   Microsoft Graph with `Sites.Selected`, web crawl of an allowlisted site, git repo). Conversion to
   markdown with structure kept (Docling or MarkItDown), images described optionally.
2. **Two serving modes, chosen per KB by size**: `files` (converted markdown mounted read-only in
   the workspace; the agent greps — enough for a 100-document framework in most cases) and `index`
   (contextual chunks, hybrid search exposed as an MCP tool `knowledge.search` returning citations).
3. **Citations mandatory** in outputs that use a KB; the architect's review cites the framework
   section it applies.
4. **Freshness**: delta sync for connectors, a visible "last synced" and per-document status.
5. **Evals per KB**: a few questions → expected documents; recall shown on the KB page.
6. **Distillation (cheap, high value)**: an agent compiles a KB into a reviewed *principles skill*
   (e.g. "architecture principles checklist"); the skill is versioned and pinned like any other.
7. **Separation kept**: KB = curated reference corpus (read-only); Ecphoria memory = facts learned
   from work (proposed, accepted). Same search tool, two scopes.

### Item 9 — Members

### Item 12 — Prod train 500 (fix first)

- `RealTemporal.query`: `asyncio.wait_for(…, 3 s)`; return `None` on `RPCError NOT_FOUND`,
  `WorkflowQueryFailedError` and timeout; `trains.py` then answers from the database (`collecting`,
  empty batch). The same timeout covers the known "query task not found" on long histories
  (`workflows/train.py:51-58`).
- `FakeTemporal.query` raises like the real client for an unknown id, so the test fails without the
  fix.
- A problem+json handler for unhandled 500s (the console showed `statusText` because the body was
  plain text).
- Web: environments from `policy.release_train`, not the hard-coded `["prod","staging"]`
  (`trains/page.tsx:11`).
- Same area, found on the way: `metriques.py:324` queries `"status"` (the workflow defines
  `status_query`) and reads `live["state"]` (the workflow returns `"status"`): the train
  freeze/state metrics have always been empty.
