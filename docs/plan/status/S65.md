| S65-01 | S65 | ✅ | — | A run that ended stays ended ([ADR 0143](../../adr/0143-a-run-that-ended-stays-ended.md)). A run is over for the platform before it is over for its process — a cancel that fails, a pod slow to die, a queued pod that starts late — and a run token cannot be revoked. The orchestrator stopped waiting without closing the run's row: `_abandon` asked the executor to cancel, then set `failed`, under one `suppress(Exception)`, so a cancel that raised left the run `running`, and no path wrote a result. The run's API only asked whether a result existed, on four routes. A process that outlived its run could therefore post its result — the run came back `succeeded` and its work item took that result's pull request, size, risk, scope and outputs while the next attempt ran —, call the run's tools, take a git token and read its input. Now `choregos_core.run_closure` defines *closed* once (a result, or a terminal status; `queued` or `running` without a result is open; a run has no `suspended` status, it is closed while its sandbox sleeps and `resume_run` opens it again). Every way the wait ends — budget (`timeout`), queue (`queue_timeout`), executor (`lost`), a pod that ended without a result (`invalid_result` or the executor's state), a result read from the journal, `cancel_run` (`cancelled`), the queued run of a dying interpreter (`cancelled`), a refused start — closes the row with a terminal status, `ended_at` and the result the workflow is told, in one transaction committed before the executor is asked to cancel, under the lock an update takes, never over a result already there; a cancel that fails is logged (`run.cancel_failed`, with `run_id`), and the activities raise no more than before. Every route of `/internal/runs/{id}` takes one dependency (`OpenRunAuth`, `OpenNetworkAuth`) that answers 409 `run_closed` for a closed run, after authentication; three routes are named exceptions: `result` answers `already_recorded` and changes nothing, `events` and `network/decisions` still append. The egress proxy reads that 409 as credentials it does not know (407, remembered a few seconds), and the runner, refused its egress token or its input, exits with 0. No column, no migration, no contract change, nothing under `workflows/`; the existing `reason` values are reused. **Proves**: `packages/core/tests/test_run_closure.py` (17: every `RunStatus` is open or closed, closing writes the three fields together, twice changes nothing, never over a posted result); `apps/orchestrator/tests/test_run_closed_when_the_wait_ends.py` (18, and 1 on PostgreSQL: each ending closes the row with exactly what the workflow is told, with a cancel that raises; the executor's `cancel` reads the row through another connection and finds it closed; the failed cancel is logged with its run; awaiting or cancelling again changes nothing; the runner's result is never overwritten and is what the workflow is told; a suspended run is closed asleep and open once `resume_run` ran; the running run of a dying interpreter stays open); `apps/api/tests/test_run_closed.py` (39: end to end with the real `await_run` — budget spent, cancel raising, then a late `POST result` answered `already_recorded` with the run still `failed` and the work item's `pr_url`, `size`, `risk`, `allowed_paths`, documents, events, artifacts and receipts unchanged; the 19 other routes refused with the typed problem and writing nothing, each also called on an open run; the two journals accepted; 401 and 403 before 409; a queued, a running and a resumed run served; the route table read so that a new route is guarded or named); `apps/api/tests/egress/test_proxy_with_api.py` (3 new: a closed run's network is refused and the refusal remembered, the proxy answers 407, a cached answer lasts until `cache_seconds`); `packages/runner/tests/test_egress_env.py` (2 new); on PostgreSQL, `apps/api/tests/test_run_closed_postgres.py` and the orchestrator's PostgreSQL case hold one side uncommitted while the other arrives: the later one waits, then reads the first. Red without the change: with the six source files as before, 50 of these tests fail; each guard removed alone turns its own tests red (the close before the cancel, the result written, no overwrite, the API guard, the 409 at the proxy, the runner's exit, the logged cancel, and each of the two row locks on PostgreSQL). **Does not prove**: what a process does with what was minted before its run was closed — its git token lives one hour (`contents: write` on the run's repository), the proxy serves its cached answer for up to `cache_seconds`, a tunnel already open stays open; whether a branch that moves after its gates were judged can still be merged is not looked at here. The running run of an interpreter that died is left open on purpose (a restart awaits it again), and a Temporal termination runs no code. `resume_run` asks the executor to resume before its transaction reopens the row: a pod restarted faster than that commit would be refused, as it already was its input. A run closed before this change by a status alone is refused like the others, but gets no result written after the fact. The two PostgreSQL cases need `CHOREGOS_TEST_DATABASE_URL`; SQLite has no row lock. Fakes and scripted executors only: nothing on a real cluster. The OpenAPI contract does not list the 409 on the routes that had none (a `contract-change`). |
