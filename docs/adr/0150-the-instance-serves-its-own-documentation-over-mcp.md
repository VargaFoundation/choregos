# 0150 — The instance serves its own documentation over its MCP door

- **Status**: accepted, 2026-11-11
- **Concerns**: `docker/api.Dockerfile` (stage `docs`), `apps/api/src/choregos_api/mcp/docs.py`, the
  MCP door's tools (`docs_search`, `docs_read`), the settings `CHOREGOS_DOCS_DIR` and
  `CHOREGOS_DOCS_URL`; extends [ADR 0030](0030-an-mcp-door-for-external-clients.md) §4

## Context

The user documentation moves into the product repository, under `docs/site/` (Markdown for Docusaurus),
and is published at `https://docs.varga.foundation/choregos/<slug>` (S62-09). People increasingly ask
their assistant — Claude Code, Cursor, an agent — how to do something in Choregos, and the assistant
answers from what it remembers of some other version, or from a web search it may not have.

Some documentation sites expose themselves to assistants as an MCP server with a search tool and a
read tool (docs.onyx.app/mcp, generated by Mintlify). Three ways were open to us:

1. **A public documentation MCP server**, hosted next to the public site.
2. **`llms.txt` only**: the site publishes an index and plain-text pages for assistants to fetch.
3. **The instance serves the documentation it was built with**, through the MCP door it already has.

Choregos is installed behind its customers' firewalls, often without internet access from the
workstations that reach it, and an instance may run a version several releases behind the public site.

## Decision

1. **The API image carries the documentation of its own version.** At build time the `docs` stage
   copies the `.md` and `.mdx` files of `docs/site/**` to `/opt/choregos/docs` (`CHOREGOS_DOCS_DIR`
   overrides). Images are not carried: nothing serves them through the door. A build where
   `docs/site/` is absent or empty bundles nothing, and the tools say so, with the public URL.
2. **Two read-only tools on the existing door**, announced to every token that opens it (`mcp:read` or
   `mcp:write`, OAuth or `chg_`, bound to a project or not), filtered by an external agent's version
   like any other tool (ADR 0033), audited (`mcp.call`) and rate limited like the door's reads:
   - `docs_search(query, limit)`: ranked pages, each with its title, slug, public URL
     (`CHOREGOS_DOCS_URL` + slug) and a short snippet;
   - `docs_read(slug, section, offset)`: the page's Markdown, front matter stripped, or one section by
     its heading anchor, at most 20,000 characters per call with the offset to continue from.
   The door's instructions tell the model to use them before answering how Choregos works.
3. **The index is built once, in memory, at first use**: one page per Markdown file, under the slug the
   public site gives it (number prefixes stripped, `index.md` at the folder's URL, `_` partials left
   out). The ranking is BM25 over each page's body and headings, with a boost for a match in its title.
   No new dependency: a few dozen pages do not need a search engine, and the answer must be the same
   on every replica.
4. **A slug is a key of that index, never a path.** `docs_read` cannot open a file the walk did not
   list, and the walk lists only regular Markdown files under the directory, not a symbolic link that
   leads out of it.

## Consequences

- An assistant connected to an instance reads the documentation of exactly the version that instance
  runs, offline, with the person's token and nothing more; its calls appear in the audit log.
- The image grows by the size of the Markdown (a few hundred kilobytes).
- The documentation is only as good as `docs/site/`: until S62-09 lands its pages, a build answers
  "no bundled documentation".
- The two names join those an ontology may not take (`RESERVED_TOOLS`, ADR 0030 §4).

## Alternatives discarded

- **A public documentation MCP server.** It serves the latest version, not the one installed, and an
  instance behind a firewall cannot reach it. It is one more service to host and secure. Not excluded
  for later, for people who are not on an instance; out of scope here.
- **`llms.txt` only.** Useful and cheap for assistants with internet access; the public site publishes
  one (S62-09a, in the docs repository). It does not reach an assistant on a closed network, and it
  serves the latest version.
- **Embeddings and a vector index.** Better on paraphrases, but a model to ship or call, and a ranking
  that changes with it; term matching over a small, well-titled corpus is enough and dependable.

## Out of scope

A public endpoint for the documentation (the instance serves it only through the authenticated door);
the site's `llms.txt` (S62-09a, docs repository); serving images or the site's HTML.
